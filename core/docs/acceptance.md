# Критерии приёмки: ядро консультанта (Ivan)

Каждый критерий бинарный: прошёл или не прошёл. У критерия указано, как проверить, и какие требования из [requirements.md](requirements.md) он закрывает.

Условия проверки:

- Данные кейса лежат локально в `data/`: `knowledge-base.zip`, `questions.csv` (копия демо-вопросов), образец ответов, разрешённый список зависимостей `data/requirements.txt`, dev-набор `data/dev/`.
- Имена скриптов в `core/scripts/` — предложение: `build_submit.py` (сборка ZIP в `dist/submit.zip`), `check_submit.py` (проверка архива), `check_submission.py` (проверка CSV), `fake_proxy.py` (заглушка прокси), `eval.py` (локальная оценка). Если имена изменятся, команды ниже правятся вместе с ними.
- «Заглушка» — локальная имитация прокси моделей (CORE-06). «Провайдер» — реальный доступ к моделям для разработки (Q-CORE-13).
- Числовые пороги с пометкой «предложение» меняются только строкой в decision log.
