**Q-SRV-03. Заглушка передачи заявки.** Блокирует SRV-31 и `docs/integration.md`. Варианты: (а) только строка в журнале, как в ТЗ — минимум работы, но персональные данные в журнале и нечего показать; (б) запись о передаче в хранилище, в журнале только идентификатор — видно в интерфейсе заявок; (в) то же плюс настоящий исходящий запрос, если задан адрес, — можно показать на защите, немного больше кода. Рекомендация: (в), по умолчанию адрес пуст. Этап 3.

**Q-SRV-04. Как автоматически ловить утечки.** Блокирует SRV-03. Запуск: git-хук у каждого либо проверка на стороне хостинга репозитория. Рекомендация: (в), хук плюс проверка при слиянии. Этап 1.

**Q-SRV-05. Чем проверять сабмит локально.** Блокирует SRV-23. Варианты: (а) настоящий внешний сервис — проверяет качество, но стоит денег и не воспроизводит сбои; (б) заглушка API моделей с путями генерации, эмбеддингов и реранжирования — бесплатно, без сети, умеет имитировать 429, 5xx и зависание; ответы бессмысленны; (в) оба режима. Рекомендация: (в): заглушка — обязательная проверка перед каждым сабмитом, настоящий сервис — для замеров времени. Этап 2.

**Q-SRV-06. Значения лимитов стенда.** Блокирует SRV-27. Нужны числа: длина реплики, реплик на сессию, запросов в минуту с адреса, дневной бюджет на внешний API.
