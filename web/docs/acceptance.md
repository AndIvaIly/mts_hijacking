# Веб-интерфейс чата: критерии приёмки

Каждый критерий бинарный: прошёл или не прошёл. В скобках в конце — требования из [requirements.md](requirements.md), которые он закрывает.

Условия проверки, если в критерии не сказано иное:

- браузер — актуальный Chrome, окно без сохранённых данных (режим инкогнито), открыты инструменты разработчика;
- «стенд» — развёрнутый интерфейс по ссылке с первого слайда; «локально» — запуск одной командой из README на машине со свежим клоном репозитория;
- «мок» — режим разработки с мок-сценариями из WEB-04;
- контактные данные для проверок: Соколова Марина Игоревна, +7 900 000-00-00, ООО «Северный ветер».

## Допуск к экспертной оценке

Провал любого критерия этого блока означает, что команду могут не оценивать вообще (кейс, стр. 11). Блок проходится целиком на стенде и локально после каждого изменения, затрагивающего чат, и ещё раз после заморозки кода.

- [ ] **AC-WEB-01. Чат запускается.** Свежий клон, файл `.env` по README, одна команда из README. Открыть адрес из README. Проходит, если виден пустой экран с пятью подсказками, плашка «Сервис запускается» исчезла сама не позже чем через 2 минуты после старта контейнера, а в консоли браузера нет ошибок. (WEB-02, WEB-16, WEB-18)
- [ ] **AC-WEB-02. Основной сценарий доходит до заявки.** Нажать первую подсказку → ответить на уточняющий вопрос бота → нажать «Связаться с менеджером» (или написать то же словами) → сообщить ФИО, телефон и компанию. Проходит, если без перезагрузки страницы и не более чем за 10 реплик пользователя в ленте появилась карточка «Заявка сформирована» с тремя контактами и резюме. Проверяется на стенде и локально. (WEB-06, WEB-07, WEB-19, WEB-26, WEB-27, WEB-30)
- [ ] **AC-WEB-03. Сценарий стабилен.** Повторить AC-WEB-02 три раза подряд с разными подсказками, каждый раз начиная с «Нового диалога». Проходит, если карточка получена в трёх прогонах из трёх и ни разу не показан блок ошибки. (WEB-19)
- [ ] **AC-WEB-04. Заявка и её сессия видны в прототипе.** После AC-WEB-02 открыть «Заявки». Проходит, если заявка есть в списке, открывается с резюме, а ссылка из неё ведёт на переписку именно этой сессии. (WEB-31, WEB-32, WEB-33)
- [ ] **AC-WEB-05. Сессия без заявки видна в истории.** Новый диалог, один вопрос, дождаться ответа, закрыть вкладку. Открыть «Историю» в новой вкладке. Проходит, если сессия есть в списке без отметки о заявке и её переписка открывается. (WEB-17, WEB-31, WEB-32)
- [ ] **AC-WEB-06. «Новый диалог» сбрасывает контекст.** Написать «У нас 12 магазинов в Твери», дождаться ответа, нажать «Новый диалог», спросить «Сколько у нас магазинов?». Проходит, если лента перед вопросом пуста, бот не называет ни число, ни город, а в «Истории» две отдельные сессии. (WEB-17)
- [ ] **AC-WEB-07. Режим отладки показывает время и документы.** Открыть стенд по ссылке с первого слайда, задать два вопроса по продуктам. Проходит, если под каждым из двух ответов видны время ответа в секундах и хотя бы один документ базы знаний с путём файла и разделом. (WEB-22, WEB-23, WEB-24)
- [ ] **AC-WEB-08. Первый слайд и ссылки.** Открыть PDF презентации из репозитория. Проходит, если на первом слайде есть порядок проверки, ссылка на репозиторий и ссылка на стенд, и обе ссылки открываются щелчком в окне без сохранённых данных. (WEB-43, WEB-46)

## Этап 1. Каркас на моках

- [ ] **AC-WEB-09. Решения записаны, версии зафиксированы, проверки настоящие.** В `docs/decision-log.md` есть строки с решениями по стеку, сборке и адресам страниц (Q-WEB-04…Q-WEB-06) и по контрактам (Q-WEB-07…Q-WEB-10). Открыть файл зависимостей `web/`: нет диапазонов версий (`^`, `~`, `*`, `latest`), файл блокировки есть в репозитории. Выполнить `make -C web lint` и `make -C web test`. Проходит, если обе команды завершаются успешно и выводят результаты проверок, а не строки-заглушки. (WEB-01, WEB-02, WEB-14)
- [ ] **AC-WEB-10. Шесть действий бота.** В моке по очереди вызвать ответы с каждым значением `action`. Проходит, если вид каждого ответа совпадает с таблицей действий в requirements.md, а кнопка «Связаться с менеджером» активна только у последнего сообщения. (WEB-06, WEB-07, WEB-26)
- [ ] **AC-WEB-11. Неизвестное действие.** Мок-ответ с `action: "something_new"`. Проходит, если ответ показан как обычное сообщение, экран в состоянии S2, значение видно в блоке отладки. (WEB-07)
- [ ] **AC-WEB-12. Пустой экран.** Открыть чат. Проходит, если видны приветствие, ровно пять подсказок — по одной на каждый сегмент аудитории — и предупреждение о выдуманных данных, а нажатие подсказки отправляет её полный текст первой репликой. (WEB-08)
- [ ] **AC-WEB-13. Ожидание медленного ответа.** Мок с задержкой 12 секунд. Проходит, если индикатор со счётчиком секунд виден с первой секунды, на 10-й секунде появляется строка «Ответ готовится дольше обычного», повторное нажатие Enter не создаёт второй запрос (вкладка «Сеть»: один запрос), а текст в поле ввода в это время набирается. (WEB-05, WEB-10)
- [ ] **AC-WEB-14. Ошибки.** В моке по очереди: 400, 404, 502, 504, тело не по контракту; затем в инструментах разработчика включить режим «Офлайн». Проходит, если в каждом из шести случаев показано сообщение по-русски без трассировки, есть кнопка «Повторить», текст реплики не потерян, а после устранения ошибки «Повторить» приводит к ответу. (WEB-11)
- [ ] **AC-WEB-15. Клиентский таймаут.** Мок, который не отвечает. Проходит, если через 40 секунд (±2) показан блок ошибки с кнопкой «Повторить» и поле ввода активно. (WEB-10, WEB-11)
- [ ] **AC-WEB-16. Длинный и размеченный ответ.** Мок-ответы: 10 000 символов; таблица из восьми столбцов; список; внешняя ссылка; относительная ссылка на файл. Проходит, если у страницы нет горизонтальной прокрутки, таблица прокручивается внутри сообщения, внешняя ссылка открывается в новой вкладке, а относительная показана текстом и не нажимается. (WEB-09)
- [ ] **AC-WEB-17. Ширина 360 px.** В режиме эмуляции устройства задать 360×640 и пройти мок-сценарий до карточки заявки. Проходит, если `document.documentElement.scrollWidth` не больше 360 на каждом шаге и все кнопки сценария нажимаются. Повторить на 768 и 1440 px. (WEB-12)
- [ ] **AC-WEB-18. Мок не попадает в сборку и не содержит данных кейса.** Собрать `web/` командой для Docker и открыть результат: метки «МОК» нет, ответы приходят с сервера. Ревьюер сравнивает пять случайных строк мок-сценариев с материалами в `data/`: дословных совпадений нет, тексты начинаются с «[мок]», телефоны только вида `+7 900 000-00-0X`. (WEB-03, WEB-04)

## Этап 2. Сквозной сценарий на настоящем API

- [ ] **AC-WEB-19. Нет внешних запросов.** Локальный запуск, вкладка «Сеть», пройти AC-WEB-02, открыть «Историю», «Заявки» и `demo.html`. Проходит, если все запросы идут на адрес самого приложения и нет ни одного запроса к другому домену. (WEB-13, WEB-15, WEB-16)
- [ ] **AC-WEB-20. Перезагрузка страницы.** После двух обменов репликами нажать F5. Проходит, если лента та же, а ответ на следующую реплику учитывает сказанное до перезагрузки. Повторить в состоянии сбора контактов после ввода ФИО: строка прогресса после F5 показывает ФИО отмеченным. (WEB-17)
- [ ] **AC-WEB-21. Закрытие вкладки и две вкладки.** Во вкладке А написать «Наша компания называется „Северный ветер“». Открыть вкладку Б по тому же адресу. Проходит, если вкладка Б стартует с пустого экрана, на вопрос «Как называется наша компания?» бот названия не знает, а после закрытия обеих вкладок в «Истории» две сессии. (WEB-17)
- [ ] **AC-WEB-22. «Новый диалог» во время ожидания.** Отправить вопрос и до прихода ответа нажать «Новый диалог». Проходит, если экран пуст и опоздавший ответ в ленте не появился в течение 60 секунд. (WEB-17)
- [ ] **AC-WEB-23. Пустые сессии не создаются.** Запомнить число строк в «Истории», пять раз открыть и закрыть чат без отправки реплик, три раза нажать «Новый диалог». Проходит, если число строк не изменилось. (WEB-17)
- [ ] **AC-WEB-24. Исчезнувшая сессия.** Начать диалог локально, перезапустить контейнер с очищенным хранилищем, не закрывая вкладку, отправить реплику. Проходит, если показано сообщение о том, что диалог начат заново, и следующая реплика получает ответ. (WEB-11, WEB-17)
- [ ] **AC-WEB-25. Запуск до готовности сервера.** Открыть страницу сразу после команды запуска. Проходит, если видна плашка «Сервис запускается», отправка заблокирована, а после готовности плашка исчезает без перезагрузки страницы. (WEB-18)
- [ ] **AC-WEB-26. Подсказки на настоящем ядре.** На стенде в режиме отладки нажать каждую из пяти подсказок в новом диалоге. Проходит, если в пяти случаях из пяти значение `action` — `answer` или `clarify`. (WEB-20)

## Этап 3. Качество: отладка, история, заявка

- [ ] **AC-WEB-27. Переключатель отладки.** Включить «Отладку», перезагрузить страницу — режим остался включённым. Выключить, открыть адрес с `?debug=1` — режим включён. (WEB-22)
- [ ] **AC-WEB-28. Содержимое блока отладки.** Задать вопрос по продукту на стенде. Проходит, если в блоке под ответом есть: время, измеренное интерфейсом; время сервера; значение `action`; список документов с путём файла, названием, разделом и оценкой. Раскрыть фрагмент с таблицей: текст моноширинный, столбцы выровнены, прокрутка внутри блока. (WEB-21, WEB-23, WEB-24)
- [ ] **AC-WEB-29. Отладка без данных.** Моки: пустой `sources`; отсутствующий `debug`; `timings_ms` только с ключом `total`. Проходит, если в первом случае показана строка «Документы базы знаний не использовались», во втором — время интерфейса и пометка об отсутствии данных сервера, в третьем — нет пустых строк шагов. (WEB-25)
- [ ] **AC-WEB-30. Некорректный телефон.** В сборе контактов ввести «12345». Проходит, если пункт «Телефон» не отмечен и карточки заявки нет. Затем ввести «8 900 000-00-00»: пункт отмечен, показан телефон в виде, который вернул сервер. (WEB-27, WEB-28)
- [ ] **AC-WEB-31. Пользователь передумал.** В сборе контактов нажать «Не сейчас». Проходит, если строка прогресса исчезла, всплывающих окон нет и следующий вопрос по продукту получает обычный ответ. Затем написать «Хочу связаться с менеджером»: строка прогресса вернулась и показывает то, что вернул сервер. (WEB-26, WEB-27, WEB-29)
- [ ] **AC-WEB-32. Карточка заявки.** После AC-WEB-02. Проходит, если: заголовок «Заявка сформирована»; нет срока звонка и имени специалиста; все поля резюме подписаны по-русски; пустое поле показано как «не уточнялось»; «Скопировать для менеджера» кладёт в буфер текст с тремя контактами и резюме; «Исправить данные» и новый телефон приводят к обновлению той же карточки, второй карточки и второй записи в «Заявках» нет. (WEB-30)
- [ ] **AC-WEB-33. История и заявки.** Проходит, если: список сессий отсортирован от новых к старым; у каждой строки дата, первая реплика, число сообщений, отметка о заявке; просмотр сессии не имеет поля ввода и при включённой отладке показывает блоки отладки; адрес просмотра, вставленный в новую вкладку, открывает ту же переписку; при остановленном сервере страница показывает ошибку с кнопкой «Повторить»; на обеих страницах есть строка «Демонстрационные данные», а в коде страницы — запрет поисковой индексации. (WEB-31, WEB-32, WEB-33, WEB-34)
- [ ] **AC-WEB-34. Код в данных не исполняется.** Отправить реплику `<img src=x onerror=alert(1)>` и указать её же как название компании. Проходит, если окно `alert` не появилось ни в чате, ни в «Истории», ни в «Заявках», а строка показана текстом. (WEB-09, WEB-35)
- [ ] **AC-WEB-35. Клавиатура и доступность.** Пройти AC-WEB-02 без мыши. Проходит, если фокус виден на каждом шаге и после отправки возвращается в поле ввода. Запустить аудит Lighthouse, раздел «Специальные возможности», для чата и для «Истории»: оценка не ниже 90, замечаний по контрасту нет. (WEB-13, WEB-36)
- [ ] **AC-WEB-36. Тесты.** `make -C web test` запускает не менее одного теста на каждую из тем: таблица действий, переходы состояний, жизненный цикл сессии, блок отладки без данных. Все тесты проходят. (WEB-37)
